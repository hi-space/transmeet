## 이 단계: plan (페이지 기획)

트랜스크립트와 분석 결과를 읽고 페이지의 **뼈대와 재료**를 정합니다. 문장을 다듬지 않습니다. 다음 단계(글쓰기·그림)가 트랜스크립트를 다시 뒤지지 않아도 되도록, 페이지에 들어갈 **구체적 사실을 빠짐없이** 모읍니다.

### 페이지 구성 (고정)
1. 상단: 회의 개요(한 줄 소개·일시) / 핵심 메시지(결론 한 문장 + 결론 불릿) / 백그라운드(왜 이 회의를 했는지).
2. 회의 요약: 주요 논의(주제별 결론) + 회의 전체를 담은 **개요 그림**(번호 ①②③… 가 붙은 주요 지점) + 번호별 요점.
3. 회의 결과: 결정 사항 / 액션 아이템 / 미결 사항.
4. 논의 흐름: 시간 순서의 주제 4~8개. 주제마다 제목 → 소제목+서술 단락 3~5개 → 그림.
5. 참고 자료(접힘): 공식 자료 대조 결과, 시사점, 용어 사전.
논의 흐름만 서술형이고 나머지 글은 불릿입니다.

### 할 일
- **개요 그림 설계.** 이 회의를 대표하는 구조(시스템 층, 데이터 흐름, 전후 비교, 역할 분담 등)를 고르고, 무엇을 어디에 둘지 구체적으로 적습니다: 영역(층·묶음), 요소(이름과 한 줄 설명), 연결(무엇→무엇, 무엇이 흐르는지), 요소마다 상태(`ok` 정해짐 / `new` 새로 추가 / `risk` 미확인·위험 / `prop` 조건부 제안 / `base` 기존). 번호를 붙일 지점은 4~9개.
- **주제 나누기.** 회의를 시간 순서로 4~8개 주제로 묶습니다. 잡담·인사·반복은 버립니다. 주제마다:
  - `facts`: 그 주제에서 나온 사실을 **모두** 한 줄씩(배경, 정한 것, 이유·근거, 수치, 제품명, 대안과 버린 이유, 남은 조건). 보통 6~15개. 압축하지 말고 구체적으로.
  - `figure`: 그 주제의 핵심 하나를 보여줄 그림. 종류(`compare` 전후·대안 비교 / `flow` 흐름·판단 / `layers` 구조 / `steps` 단계 / `matrix` 표형 비교 / `schedule` 일정)와 그림 설계(요소·연결·상태). 개요 그림과 같은 내용을 반복하지 않습니다.
- **정해진 것·할 일·확인할 것**을 회의에서 나온 만큼 빠짐없이(각 3~10개). 할 일은 담당·기한을 트랜스크립트에 있을 때만.
- **참고 자료**: 리서치 결과의 출처마다 제목·URL·판정(`ok` 일치 / `diff` 다름 / `na` 확인 불가)·핵심 사실. 인사이트의 시사점 2~4개.
