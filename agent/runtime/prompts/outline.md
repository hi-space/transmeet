## 이 단계: outline (구조 파악)

트랜스크립트를 끝까지 읽고 아래를 구조화해 **`Outline` 도구를 정확히 한 번 호출**해 넘깁니다. 다른 도구는 없습니다. 본문 텍스트는 한 줄 상태 문장만 쓰고, 결과를 본문에 JSON 으로 적지 않습니다.

1. `topics` — 시간 순서대로 주제 블록을 나눕니다. 3~12개. 각 항목은 `start`/`end`(`HH:MM`, 트랜스크립트의 시각을 그대로), `title`(12자 이내의 명사형 한국어 제목), `summary`(2~3문장: 누가 무엇을 제안·반박·질문했는지). 인사·잡담·기술 문제("들리세요?")만 제외하고 **모든 실질 발언이 어느 블록에든 속해야** 합니다. 짧은 미팅이면 1~3개여도 됩니다.
2. `research_targets` — 공식 출처로 확인할 외부 사실. 제품·서비스·기능 이름, 버전·GA 일정·가격·한도·지역 가용성 같은 확인 가능한 수치/일정, 표준·규격·법규, 외부 조직의 발표를 인용한 발언. 사람 이름·사내 프로젝트명·내부 일정은 **대상이 아닙니다**. 미팅 결정에 영향을 준 것을 우선해 **최대 10개**. 각 항목: `claim`(미팅에서 말한 내용 한 문장), `said_at`(`HH:MM`), `query`(영어 검색어, 200자 이내). 없으면 빈 배열.
3. `diagram_plan` — `timeline` 하나는 항상 넣습니다(코드가 주제 분할로 자동 생성). 그 외에 순서·분기가 있는 의사결정 흐름이 있으면 `flow`, 3개 이상 구성요소·시스템의 관계를 논의했으면 `relations` 를 **최대 2개** 추가합니다. 단순 나열이나 2개 이하 항목은 그리지 않습니다. 각 항목에 `title` 과 `rationale`(어느 주제의 어떤 발언 때문인지).
4. `glossary_candidates` — 미팅에 실제 등장한 영어 용어·약어 (최대 15개).
