## 이 단계: analyze (녹취록 분석)

페이지를 쓰기 전에 트랜스크립트를 **끝까지 읽고 분석**합니다. 결과는 **`Analysis` 도구를 정확히 한 번 호출**해 넘깁니다. 다른 도구는 없습니다. 본문 텍스트는 한 줄 상태 문장만 쓰고, 결과를 본문에 JSON 으로 적지 않습니다.

1. `terms` — 미팅에서 **자주 쓰이거나 논의의 중심인 기술 용어·제품·서비스·약어·계약/프로그램 이름**. 10~25개. 각 항목:
   - `term`: 정식 표기. 영문 제품·약어는 공식 표기(예: `Databricks`, `MACC`, `Amazon Bedrock`, `EDP`), 한국어 개념어는 한국어.
   - `variants`: 녹취에 등장한 다른 표기 전부. **음성 인식 오류를 반드시 찍어냅니다** — 예: "MSCC"→`MACC`, "블레이크"/"데이터 레이크"→`레이크`, "데이터베이스 서버리스 프리미엄"→`Databricks`, "에이전트 코어"→`AgentCore`. 발음이 비슷한 다른 단어가 맥락상 이 용어를 뜻하면 포함합니다.
   - `meaning`: **이 미팅의 맥락에서** 무슨 뜻으로 쓰였는지 한 줄(일반 사전 정의가 아니라 "고객이 Azure 와 맺은 사용 약정으로, 소진 시점이 이전 일정을 좌우함"처럼). 확실하지 않으면 "(추정)" 을 붙입니다.
   - `count`: 변형 표기를 합친 대략의 언급 횟수.
2. `summary` — **회의 전체를 모르는 사람이 읽을 요약.** 소제목 그룹 목록이며, `heading` 은 `배경·목적` → `주요 논의` → `합의·결정` → `남은 일` 중 해당하는 것을 이 순서로 3~4개. 각 그룹의 `points` 는 불릿 문자열 목록(불릿 하나는 1~2문장).
   - **디테일을 줄이지 않습니다.** 문단으로 썼을 때 들어갈 사실 — 무엇이 제안·반박·질문됐는지, 붙은 조건, 근거, 수치, 일정, 남은 확인 사항 — 을 전부 불릿으로 옮깁니다. 그룹당 불릿 수는 제한하지 않습니다(보통 2~6개). 서술을 줄이는 것이 아니라 **문단을 불릿으로 쪼개는** 작업입니다.
   - 불릿마다 **핵심 구절 하나를 `<b>…</b>`** 로 감쌉니다. 불릿 앞쪽에 두어 그 구절만 읽어도 뜻이 통하게 합니다(예: `<b>자격 증명은 OIDC</b> — 장기 액세스 키 대신 …`). 수치·일정·기한은 `<mark>…</mark>` 로 감쌉니다(예: `<mark>금요일</mark>`, `<mark>약 15분</mark>`). 그 밖의 HTML 태그는 쓰지 않습니다(글자로 보입니다).
   - 발언자 라벨 없이 "~라는 의견이 나왔다", "~로 정리됐다" 로 씁니다. 수치·일정은 발언에 있는 것만. 용어는 `terms` 의 정식 표기로.
3. `topics` — 시간 순서대로 주제 블록을 나눕니다. 3~12개. 각 항목은 `start`/`end`(`HH:MM`, 트랜스크립트의 시각을 그대로), `title`(12자 이내의 명사형 한국어 제목, 정식 용어 표기 사용), `summary`(2~3문장: 무엇이 제안·반박·질문됐는지). 인사·잡담·기술 문제("들리세요?")만 제외하고 **모든 실질 발언이 어느 블록에든 속해야** 합니다. 짧은 미팅이면 1~3개여도 됩니다.
4. `research_targets` — 공식 출처로 확인할 외부 사실. 제품·서비스·기능 이름, 버전·GA 일정·가격·한도·지역 가용성 같은 확인 가능한 수치/일정, 표준·규격·법규, 외부 조직의 발표를 인용한 발언. 사람 이름·사내 프로젝트명·내부 일정은 **대상이 아닙니다**. 미팅 결정에 영향을 준 것을 우선해 **최대 10개**. 각 항목: `claim`(미팅에서 말한 내용 한 문장), `said_at`(`HH:MM`), `query`(영어 검색어, 200자 이내). 없으면 빈 배열.
5. `diagram_plan` — `timeline` 하나는 항상 넣습니다(코드가 주제 분할로 자동 생성). 그 외에 순서·분기가 있는 의사결정 흐름이 있으면 `flow`, 3개 이상 구성요소·시스템의 관계를 논의했으면 `relations` 를 **최대 2개** 추가합니다. 단순 나열이나 2개 이하 항목은 그리지 않습니다. 각 항목에 `title` 과 `rationale`(어느 주제의 어떤 발언 때문인지).
