# TransMeet 음성 인식 비교 — 2026-10-28

중단된 세션의 한국어 비교를 이어서 완료했다. 기존 Whisper·Transcribe·Nemotron 결과는 그대로 보존하고, **동일한 WAV 10개**로 Qwen3-ASR을 추가 측정했다. Qwen은 전체 문장, 2초 분할, 6초 분할 조건에서 각각 10/10개 요청에 성공했다.

측정 당시 SageMaker 엔진의 앱 기본 전송 간격은 2초였다. 이 결과를 바탕으로 후속 코드 변경에서 기본값을 6초로 늘렸다. 아래 수치는 각 측정 조건의 결과를 그대로 보존한다.

## 결과 해석

- 전체 문장에서 Qwen과 Transcribe의 문자 오류율은 **2.68%로 동률**이었다. 두 모델의 오류가 발생한 문장은 서로 달랐다. Qwen이 더 적게 틀린 문장 4개, 같은 문장 3개, 더 많이 틀린 문장 3개였다.
- 측정 당시 앱과 유사한 2초 분할에서 Qwen은 **19.69%**로, Whisper(43.40%)와 Nemotron(23.71%)보다 낮았다. 다만 이 수준을 그대로 실시간 회의에 충분한 품질이라고 판단하기는 어렵다.
- Qwen 입력을 6초로 늘리면 오류율은 **5.82%**로 내려갔다. 모델 선택과 함께 입력 문맥을 보존하는 방법이 중요하다. 6초 고정 버퍼는 입력을 기다리는 시간도 늘리므로 실시간 지연과 교환 관계가 있다.
- 이번 배포 구성에서 Qwen은 가장 빠른 엔진은 아니었다. 전체 문장 처리시간 중앙값은 2.50초였다.
- 현재 앱의 즉각적인 실시간 자막에는 Transcribe를 우선 유지할 근거가 있다. Qwen은 문장 또는 발화 단위 문맥을 보존하는 경로에서 검토할 만하다. 이는 아래의 작은 표본에 한정한 판단이다.

## 정확도

CER은 정답 문자 수 대비 삽입·삭제·치환 오류 수이며 낮을수록 좋다. NFKC 정규화 후 대소문자·공백·문장부호를 무시했다. 숫자/한글 수사 및 단위 표기는 임의로 동등하게 바꾸지 않았다.

| 엔진                   | 전체 문장 CER | 6초 분할 CER | 2초 분할 CER |
| ---------------------- | ------------: | -----------: | -----------: |
| Amazon Transcribe      |         2.68% |            — |            — |
| Qwen3-ASR 1.7B         |         2.68% |        5.82% |       19.69% |
| Whisper large-v3-turbo |         3.58% |       15.44% |       43.40% |
| Nemotron 3.5 ASR 0.6B  |         9.84% |            — |       23.71% |

Transcribe는 하나의 지속 스트리밍 세션으로 전체 녹음을 전달했다. SageMaker 모델처럼 각 조각을 독립 요청으로 보내는 실험은 하지 않았으므로 분할 열은 빈칸이다. 이 실험에는 실제 마이크 입력, 서버 버퍼 타이머, 무음·환각 필터, 번역 지연은 포함하지 않았다.

## 처리시간

이미 녹음된 파일을 전송하기 시작한 때부터 최종 인식 결과까지의 벽시계 시간이다. Transcribe에는 실시간 속도로 대기하지 않고 오디오를 보냈다. **실시간 자막이 나타나는 지연 시간도, 엔진 기동 시간도 아니다.** RTF는 전체 처리시간 합계 / 음성 길이 합계이며 낮을수록 좋다.

| 엔진                   | 전체 문장 처리시간 중앙값 |   RTF |
| ---------------------- | ------------------------: | ----: |
| Amazon Transcribe      |                    2.79초 | 0.250 |
| Qwen3-ASR 1.7B         |                    2.50초 | 0.228 |
| Whisper large-v3-turbo |                    2.25초 | 0.206 |
| Nemotron 3.5 ASR 0.6B  |                    1.92초 | 0.175 |

Qwen의 2초 분할은 원본 녹음 하나를 여러 요청으로 순차 처리한 시간의 중앙값이 8.45초였고, 6초 분할은 4.38초였다. 이를 조각 한 개의 자막 지연으로 읽으면 안 된다.

Qwen 준비 대기는 이번에 **385.56초(약 6분 26초)**였다. 시작 상태는 복제본 0개, 종료 중(Updating), GPU 호스트 1대가 남아 있는 상태였다. 따라서 이 수치는 모든 GPU가 0대인 상태에서의 일반적인 콜드 스타트 성능으로 일반화할 수 없다. 인식 시간 표에는 이 대기를 넣지 않았다.

Qwen 실행 호스트는 `ml.g6.2xlarge`였다. 이전 세션과 실행 시각·서빙 방식이 다르므로 이 표는 배포 구성의 관측값이며, 동일 하드웨어에서 모델 연산 속도만 비교한 실험이 아니다.

## 원문에서 확인한 현상

Qwen의 2초 분할 결과에는 한국어 음성에서 `的`, `朝鲜`, `Siciliano, orromantic.`, `French, Arabic.` 같은 출력이 섞였다. 특히 마지막에서 두 번째 녹음은 2초 분할에서 49자 오류를 냈지만 전체 문장에서는 5자 오류였다. 이 한 녹음이 Qwen 2초 조건의 오류 88자 중 절반 이상을 차지하므로 평균만으로 안정성을 단정할 수 없다.

Nemotron은 `15`를 `십오`, 연도를 한글 수사로 출력한 사례가 있다. Whisper와 Qwen도 숫자·단위 표기가 정답과 다른 경우가 있었다. 이 차이도 CER에 포함되므로 점수 차이를 전부 의미 전달 실패로 해석하면 안 된다.

## 평가 범위와 재현

- FLEURS `ko_kr`, test 행 0–9. 한국어 낭독 음성 10개, 총 111.12초, 정규화한 정답 447자.
- 각 조건 1회 측정. 무작위 대규모 표본이나 실제 회의 테스트가 아니다.
- 영어, 회의 잡음, 겹치는 발화, 화자 분리, 번역 품질, 동시 사용자 처리량은 측정하지 않았다.
- Qwen은 현재 어댑터와 동일하게 자동 언어 감지를 사용한다. Transcribe와 Nemotron에는 한국어를 지정했다. 기존 Whisper 기본 결과는 자동 감지다.
- 이전 세션의 원본 결과와 새 Qwen 결과는 `raw/`, 전체 요약은 `summary.json`, 문장별 비교는 `paired-clip-comparison.json`에 있다.
- 입력 WAV와 해시는 `audio/` 및 `manifest.json`, 출처·라이선스는 [SOURCE.md](SOURCE.md)에 보존했다.

저장소 루트에서, 엔진이 준비된 상태로 다음 명령을 실행한다. 호출에는 AWS 사용료가 발생한다.

```bash
REGION=us-east-1 QWEN_ASR_ENDPOINT=transmeet-qwen3-asr \
QWEN_ASR_INFERENCE_COMPONENT=transmeet-qwen3-asr-ic-v2 \
python backend/scripts/benchmark_stt.py \
  benchmarks/stt-comparison-2026-10-28/manifest.json \
  --providers qwen3-asr --chunk-seconds 0 \
  --output /tmp/qwen-full.json --timeout 120
```

`--chunk-seconds`를 2 또는 6으로 바꾸면 해당 조건을 재현할 수 있다. 기본 모델/계산 코드와 버전 정보는 `provenance.json`에 기록했다.

참고: Transcribe의 스트리밍/부분 결과 개념은 [AWS 공식 문서](https://docs.aws.amazon.com/transcribe/latest/dg/streaming-partial-results.html)에 설명되어 있다. 위 수치는 이 문서의 성능 수치가 아니라 이 폴더에 저장한 실제 측정값이다.
