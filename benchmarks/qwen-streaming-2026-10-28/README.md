# Qwen 스트리밍 구현·튜닝 기록

배포 검증 완료 후 새로 실행한 네 모델의 최종 성능 비교는 [최종 보고서](../stt-streaming-comparison-2026-10-28/final/README.md)에 있다. 이 디렉터리는 구현 과정의 튜닝·재현·배포 증거이며 최종 비교와 실행 시점이 다르다.

| 갱신 설정 | 한국어 CER | 영어 WER | 한국어 첫 부분 자막 | 영어 첫 부분 자막 |
|---|---:|---:|---:|---:|
| 1초 | 4.25% | 3.79% | 1.25초 | 1.21초 |
| 2초 | 4.25% | 3.79% | 2.26초 | 2.22초 |

첫 부분 자막은 모델/API 연결의 ready 이후 음성 수집 시작을 기준으로 측정했다. 실제 앱의 녹음 시작에는 별도 SDK 프로세스와 연결 준비 시간이 추가되며, 그 값은 최종 보고서에 따로 기록했다.

동일 정확도에서 첫 자막이 빠른 1000ms를 서비스 설정으로 선택했다. 브라우저 음성 전송 간격은 160ms다. 부분 자막은 수정되며 확정된 발화만 번역·저장한다. 한국어·영어 지정과 자동 감지를 지원한다.

최종 Qwen 모델은 서울 `transmeet-qwen-streaming`, `ml.g6.xlarge` 1대, 이미지 `sha256:31fd09210793be44424f5d45270d99ceb26c2dc4bcd5e8ff962048631def63d3`다. 시간당 1.3854 USD이며 다른 서비스 비용은 별도다.

처음 사용한 고정 RMS 기준은 작은 영어 음성을 모델 호출 전에 버렸다. 해당 실패 결과를 `smoke-en.json`에 보존했고, 이후 모든 비영(非零) PCM을 보존하도록 바꿨다. 20개 입력의 바이트 단위 보존 검증과 실제 조용한 음성 재검증은 `deployment-retention-*`, `smoke-quiet-corrected.json`에 있다. 배경 소음도 모델에 들어갈 수 있어 의미 없는 인식이 완전히 사라지는 방식은 아니다.

한국어 UTF-8 토큰 경계에서 종료 결과가 깨지던 공식 API 경로를 실제 토크나이저로 재현해 보호했다. SDK는 기존 Transcribe와 충돌하지 않도록 분리된 Python 프로세스를 재사용한다.

기존 배치 Qwen의 모델 및 설정은 보존했다. 풀 기반 배치 호스트의 0대 전환은 추가 GPU 할당량이 필요해, 검증된 네이티브 서버로 전환한 뒤 사용하지 않는 배치 엔드포인트·컴포넌트만 제거했다. 복원 메타데이터는 [보존 기록](../stt-streaming-comparison-2026-10-28/legacy-qwen-restorable.json)에 있다.
