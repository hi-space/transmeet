Vision 60 아키텍처 변경 방안 논의

— 2026-07-27 10:33–12:24 (1시간 50분)

Vision 60 은 Jetson Thor 가 판단하고 Jetson Xavier 가 움직이는 두 층 구조로 간다.

LiDAR·상부 카메라는 Jetson Thor 에 붙이고, 클라우드는 AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams 세 가지로 본다. 다만 제조사의 저수준 제어 개방, 탑재 후 구동시간, 교육 일정은 아직 비어 있다.

왜 이렇게 바꾸나

Vision 60 내장 Jetson Xavier 는 하위단으로 두고, Jetson Thor 의 제어를 받는 VCU로 쓴다. Jetson Thor 는 관제·주행 플래닝·매핑을 맡고, 둘은 Vision 60 본체의 RJ45 커넥터로 이더넷 통신을 한다. 기존에 아키텍처를 모르고 만든 에셋을 못 쓰게 된 경험이 있어, 이 구조를 먼저 고정하고 교육을 빨리 잡자는 것이 회의의 출발점이었다.

"Jetson Xavier 는 약간 VCU 역할을 하는 거예요."[10:35]

센서는 위층으로 모인다. 내장 뎁스 카메라 두 개가 바닥을 보고 있어 퍼셉션에는 부족하므로 상부에 카메라를 따로 달고 LiDAR 는 Jetson Thor 에 직결한다. 클라우드 쪽은 산업안전 데모(Unitree Go2·Jetson Orin)가 거의 같은 구성으로 시연됐다.

"뎁스 카메라가 아래쪽으로 보고 있습니다. 그래서 … 카메라를 따로 달려고 하고 있고요."[10:38]
"아까 그 구조가 그냥 딱 그 구조인 것 같아요."[11:56]

정해진 것

회의에서 정리되거나 이미 진행 중인 방향

  • 두 층 연산 구조 — Jetson Xavier 는 액추에이터 제어·기본 통신, Jetson Thor 는 관제·주행 플래닝·매핑을 맡고 RJ45 이더넷으로 잇는다. [10:35]·[10:36]
  • 센서 조합 — 내장 뎁스 카메라 + 상부 카메라 + 고정 LiDAR 로 가며, LiDAR 는 Jetson Thor 에 직접 연결한다. [10:38]·[10:40]
  • 오도메트리 — 내장 IMU 는 시프트가 생겨 쓰지 않고 LiDAR 내장 IMU 를 쓴다. [10:58]
  • SLAM·가감속 제어 자체 개발 — FAST-LIO2 는 실사용 성능이 떨어져 따로 만들고, 가감속 제어도 기본 로직 대신 직접 만든 것을 얹는다. [11:04]
  • AWS 서비스 범위 — AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams 세 가지만 기억하면 된다고 정리됐다. RL 정책만 학습하면 Amazon SageMaker AI 는 이번엔 불필요하다는 의견. [11:16]·[11:17]
  • 클라우드 학습 시점 — 클라우드는 로컬보다 느리므로 로컬 PC 에서 환경·알고리즘을 정의한 뒤 대규모 확장 테스트 단계에서 옮기라는 권고. [11:56]
  • 현장 투입 — 시뮬레이션만으로는 튜닝 한계가 있어 현장은 자주 갈수록 좋고, 8월 중순 정도부터 수동 운용 형태로 투입 가능하다. [12:17]·[12:18]
  • 지원 체계 — AWS 팀은 원래 파트너를 직접 지원하지 않으며, 이번 건은 고객 지원 프로그램으로 진행한다. [12:20]·[12:21]
  • 문의 창구 — 지원 요청은 망설이지 말고 메일 루프로 보내면 전문가 네 명 중 한 명이 답하고 에셋을 공유한다. [12:22]

권장 조치 (회의 밖, 추정)

  • 제조사에 서면 확인 — 발 모터 제어, 가감속 제어 교체, 카메라 하위 접근이 각각 가능한지. LIG Nex1 경로 활용 가능. 담당·기한 미정.
  • Jetson Thor 저장 구성 — 캐리어 보드의 NVMe 구성과, 분해 없이 데이터를 꺼내는 방식(외부 USB SSD 안 포함)을 함께 정한다.
  • 8월 중순 전 측정 — 전 장비 탑재 상태의 구동시간, NVENC 압축 시 360도 영상 1시간 분량.

남은 위험·미결

추정은 표시했다

  • 저수준 모터 제어 — 계단 전환 시 발 모터단 제어가 필요한데, 하위단 접근은 "다 열려있고 되진 않아서" 깊이 손대지 못했다. 저수준 제어 가능 여부는 확인되지 않았다. [10:38]·[11:04]
  • Ghost Robotics 데이터 개방 — 어느 정도 열어 준다고 했으나 실제로는 제한적이라는 우려. [10:40]
  • 교육 일정 공백 추정 — 날짜·아젠다가 "뽑아 볼게요" 단계라, 세팅보다 늦어지면 에셋 재작업이 되풀이될 수 있다. [12:21]
  • 구동시간 추정 — 3시간 이상은 추가 장비가 없을 때 기준(사양과 일치). Jetson Thor(40–130 W)·상부 카메라·LiDAR 를 더한 상태는 재지 않았다. [10:37]
  • Jetson Thor 모듈 저장 장치 — 1TB NVMe 는 개발자 키트 구성품이고 모듈에는 없다(공식 사양과 상이). 캐리어 보드에 저장 장치를 따로 구성해야 한다. [10:57]
  • 데이터 업로드 방식 — SSD 교체·Wi-Fi 자동 업로드·압축 중 무엇으로 갈지 정하지 않았다. [12:02]
  • 이더넷 대역폭 추정 — 카메라 데이터를 Jetson Xavier 에서 Jetson Thor 로 다시 넘겨야 하는데, 같은 링크에 제어 명령도 실린다. [10:38]
  • 현장 네트워크 추정 — 실시간 관제는 네트워크 연결이 전제이고, 용인 현장 망 조건은 다루지 않았다. 망이 약하면 데모식 원격 모니터링은 현장에서 쓸 수 없다. [11:42]
  • 현장 방문 시점·담당 — 용인 실측과 두 차례 방문이 거론됐고 울산은 시험장으로 어렵다고 했으나 시점·담당 미정. [12:16]·[12:17]
  • 총판 이관 — KRM 종료 후 LIG Nex1 으로 넘어갔다는 설명은 공식 자료로 확인 불가. LIG Nex1 이 Ghost Robotics 지분 60%를 가진 점은 확인. [10:41]

근거 — 주제별 논의

필요한 주제만 펼쳐 읽는다. 시간 순서.

10:33–10:40Vision 60 구조 변경

Jetson Xavier 를 VCU 로, Jetson Thor 를 상위 연산으로 두고 RJ45 이더넷으로 잇는 구조가 설명됐다. Jetson Thor 추가로 전력 분배와 구동시간이 달라질 수 있다는 질문에는 기본 3시간 이상을 보고 있고, YOLO 전용 연산 장치를 올려 전력을 줄이려 한다는 답이 나왔다. 카메라가 Jetson Xavier 에 붙어 있으면 데이터를 다시 올려야 한다는 지적이 있었고, 하위단까지 뜯는 것은 쉽지 않았다고 했다.

10:40–10:53제조사·공급망 상황

중국산을 제외하고 비교 분석했을 때 Ghost Robotics 가 그나마 나았다. 데이터 개방 약속은 실제로는 제한적이라는 우려가 나왔고, 국내 총판은 KRM 이 올해 4월 종료돼 LIG Nex1 이 넘겨받았다는 설명이 있었다.

"Ghost Robotics 에서 데이터를 오픈을 어느 정도 해준다고 했는데 좀 아닌 것 같은 느낌이 드네요."[10:40]
10:57–11:05Jetson Thor 저장·SLAM·제어

Jetson Thor 는 1TB 를 쓰고 내부를 열어 SSD 를 하나 더 꽂는 방식이며, 개발자 키트가 아니라 모듈을 쓴다. 내장 IMU 는 시프트로 쓰지 않고 LiDAR 내장 IMU 를 활용한다. 평지·경사는 로봇 본체에 맡겨도 되지만 계단 전환에는 발 모터단 제어가 필요하다.

"계단을 올라가고 이거를 스위칭할 때는 사실은 저희가 제어할 필요가 있거든요."[11:04]
11:16–11:18핵심 AWS 서비스

Amazon SageMaker AI 는 MLOps 환경이 필요한 별도 모델 학습용이라 RL 정책만이면 불필요하고, Amazon Bedrock 은 LLM 서빙용으로 소개됐다. 데이터 수집·모델 배포는 AWS IoT Greengrass·AWS IoT Core, 실시간 영상은 Amazon Kinesis Video Streams(WebRTC·HLS)로 하며 워크숍으로 실습하자는 제안이 있었다.

"세 개 정도만 기억하시면 될 것 같아요."[11:17]
11:29–11:36데이터 파이프라인 사례

Amazon S3 에 하이브 파티셔닝으로 L0(원시)·L1(가공)·L2 를 두고 Amazon EKS 로 처리하며 DynamoDB 에 메타 정보를 넣는 구성이 소개됐다. Amazon Kinesis Video Streams 는 약 4초 지연으로 지난 영상까지 CCTV 처럼 볼 수 있다. LiDAR 원시 데이터는 너무 무거워 온프레미스가 더 빠를 수 있다는 의견, Isaac Lab 학습·시뮬레이션 분리와 Isaac Sim AMI 제공도 언급됐다.

"비디오 데이터가 오는 90% 이상은 다 쓸모없는 데이터입니다."[11:31]
11:36–11:46AWS 산업안전 데모

Unitree Go2·Jetson Orin 위 YOLO 를 AWS IoT Greengrass 로 배포하고, Amazon Kinesis Video Streams·AWS IoT Core(MQTT)·Grafana 로 영상·메트릭·원격 제어를 구현한 데모다. 네트워크 연결이 전제이고, 그대로 되어 있는 것이 아니라 개발이 필요하다. 비용은 IoT 서비스가 가장 싸고 Amazon Bedrock 은 토큰 기반이다.

"confidence 값이 나올 거잖아요. 그게 너무 낮다 하면은 … 추론을 보내는 형태로 저는 할 것 같아요."[11:45]

추정 바닥에 물이 있는 경우 같은 룰 기반 플래너의 예외 상황(주제 7)에 이 구성을 쓸 수 있다. 다만 지연 때문에 주행 판단이 아니라 상황 판단에만 맞다.

11:46–11:57Isaac Sim 클라우드 학습

AI 모델이 로봇 제어 메시지를 직접 생성하는 구현이 소개됐다. Amazon EC2 하나에 ROS·Isaac Sim·통신 프로토콜을 세팅해 복제하고, AWS Batch 로 환경 ID·로봇·에폭 같은 파라미터를 일괄 제어하거나 SSH·DCV·Slurm 으로 개별 제어할 수 있다. 여러 노드의 경험 데이터는 스토리지로 동기화해 하나의 모델을 학습한다.

"한꺼번에 확장시켜서 … 테스트를 해야 된다 했을 때 … 클라우드로 옮기시는 걸 추천드려요."[11:56]
11:59–12:03대용량 데이터 업로드

1시간 360도 영상을 무선으로 올리는 데 매우 오래 걸렸다. 이더넷 도킹은 가능하지만 느리고 불안정해, 스토리지를 물리적으로 옮기는 것이 가장 빠르다는 데 의견이 모였다. 대안은 특정 Wi-Fi 자동 업로드와 NVIDIA 인코더 압축이다(위 표).

"이더넷으로 데이터를 전송하는 건 진짜 너무 느립니다."[12:01]
12:16–12:20현장 일정·데이터

두 차례 방문과 용인 현장 실측이 거론됐고 울산은 시험장으로 어렵다고 했다. 처음에는 자율주행 없이 수동으로 투입하며 8월 중순 정도부터 가능하다. 플랜트 LiDAR 스캔 데이터 제공과 설계·시공 분리 법규도 언급됐다.

"로봇은 현장에 자주 가면 좋습니다."[12:17]
12:20–12:24지원 체계·후속 조치

이번 건은 파트너 지원이 아닌 고객 지원 프로그램이라는 점이 강조됐다. 교육·워크숍 아젠다와 날짜를 뽑아 8월 말~9월 초 투입 전 세팅을 마치고, 이후 Q&A 세션과 메일 루프로 문의를 받는다. 3사가 함께 레퍼런스를 쌓자는 구상이 공유됐다.

"무조건 메일 주세요."[12:22]
공식 자료 대조 (조회일 2026-10-28)
  • Ghost Robotics — Vision 60 사양확인됨 — 내장 컴퓨터 Jetson Xavier, 연속 보행 3시간 이상. 뎁스 카메라 장착 방향은 사양에 없음.
  • LIG Nex1 의 Ghost Robotics 인수 보도자료확인 불가 — 2024년 7월 지분 60% 인수는 확인, 국내 총판 이관은 출처에 없음.
