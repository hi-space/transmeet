Vision 60 연산 구조를 Jetson Thor 중심으로 바꾼다

Jetson Xavier는 VCU만 맡고, 새로 올리는 Jetson Thor가 관제·플래닝·매핑과 퍼셉션을 맡는다.

클라우드 쪽 핵심은 AWS IoT Greengrass, AWS IoT Core, Amazon Kinesis Video Streams 세 가지다. 대용량 데이터 회수 방식, 제조사의 하위단 접근, 교육 일정은 아직 정하지 못했다.

지도 읽기

  1. 1

    연산은 두 층으로 나눈다

    • Jetson Thor — 관제, 주행 플래닝, 매핑을 맡는다.
    • Jetson Xavier — VCU로서 액추에이터 제어와 기본 통신만 한다.
    • 연결 — Vision 60 본체의 RJ45 포트로 이더넷 통신한다.
    • 저장 장치 — Jetson Thor 모듈에는 개발자 키트의 1TB NVMe가 없어 따로 붙여야 한다.
  2. 2

    퍼셉션 센서는 Jetson Thor에 붙인다

    • LiDAR 직결 — 고정형 LiDAR를 Jetson Thor에 바로 연결한다.
    • 상부 카메라 추가 — 내장 뎁스 카메라는 바닥을 향해 퍼셉션에 쓰기 어렵다.
    • 최종 조합 — 뎁스 카메라, 상부 카메라, 고정형 LiDAR로 간다.
    • YOLO 전용 연산 장치 — Jetson Thor에 올려 전력 소모를 줄인다.
  3. 3

    위치추정과 보행 제어는 직접 만든다

    • 오도메트리 — 본체 IMU는 시프트가 생겨 LiDAR 내장 IMU를 쓴다.
    • SLAM — FAST-LIO2는 실사용 성능이 부족해 자체 개발한다.
    • 가감속 제어 — Vision 60에는 기본 제어만 남기고 직접 만든 로직을 얹는다.
    • 계단 전환 — 평지·경사는 본체에 맡기고, 계단 전환은 발 모터를 직접 제어해야 한다.
  4. 4

    클라우드 연결은 세 서비스로 충분하다

    AWS 산업안전 데모(Unitree Go2, Jetson Orin)가 같은 구성을 이미 돌렸다. 데모의 Jetson Orin 자리에 Jetson Thor를 넣으면 이번 구조가 된다. (추정)

    • AWS IoT Greengrass — 클라우드에서 학습한 YOLO 모델을 Jetson 장치로 배포한다.
    • AWS IoT Core — MQTT로 메트릭을 올리고 원격 제어 명령을 내린다. 결과는 Grafana로 본다.
    • Amazon Kinesis Video Streams — WebRTC·HLS로 실시간 영상을 본다. 지연은 약 4초다.
    • 전제 조건 — 모두 네트워크가 있어야 돌고, 연동은 직접 개발해야 한다.
  5. 5

    예외 상황은 VLM에 묻는다

    하드코딩한 플래너는 바닥에 물이 있는 경우 같은 예외에 약하다. 이 구성으로 그런 예외를 다룰 수 있다. (추정)

    • 2차 판단 — 신뢰도가 낮은 장면만 Amazon Bedrock의 VLM에 보낸다.
    • 비용 — IoT 서비스가 가장 싸다. Amazon Bedrock은 토큰 단위로 과금한다.
    • 모델 선정 — Anthropic·OpenAI·NVIDIA 모델을 현장 이미지로 테스트해 고른다.
  6. 6

    데이터는 Amazon S3에 계층으로 쌓는다

    • 계층 — L0에 원시 데이터, L1에 가공 데이터를 하이브 파티셔닝으로 넣는다.
    • 처리 — Amazon EKS로 여러 Amazon EC2를 묶어 빠르게 처리한다.
    • 메타 정보 — DynamoDB에 구간별 인덱스를 둔다.
    • 선별 — 비디오 데이터의 90% 이상은 쓸모없다. 무엇을 남길지는 직접 로직을 짠다.
  7. 7

    학습 환경은 로컬에서 정하고 클라우드에서 넓힌다

    • Isaac Sim AMI — AWS Marketplace AMI로 바로 띄운다. AMI는 무료이고 EC2 비용은 따로 든다.
    • 복제 — ROS·Isaac Sim·통신 설정을 EC2 하나에 하고 그대로 복제한다.
    • 제어 — AWS Batch로 환경 ID·로봇·에폭을 한 번에 넘긴다. 개별 제어는 SSH·DCV로 한다.
    • 속도 — 클라우드는 로컬보다 느려 확장 테스트 단계에 옮긴다.
  8. 8

    대용량 데이터를 꺼낼 방법이 아직 없다

    1시간 분량 360도 영상은 올리는 데 매우 오래 걸린다. 어느 방식으로 갈지 정하지 않았다.

    • 압축 지원 — NVIDIA Video Codec SDK가 Jetson Thor 하드웨어 인코딩을 지원한다.
    • USB SSD — 외부 USB SSD로 빼는 안도 후보다.
    • LiDAR 원시 데이터 — 너무 무거워 온프레미스 처리가 더 빠를 수 있다.
  9. 9

    현장 투입과 지원 체계

    • 현장 방문 — 시뮬레이션만으로는 튜닝에 한계가 있어 자주 갈수록 좋다.
    • 투입 시점 — 8월 중순부터 수동 운용으로 투입할 수 있다.
    • 현장 후보 — 용인 현장에서 실측한다. 울산은 시험장으로 쓰기 어렵다.
    • 지원 형태 — 이번 건은 AWS의 고객 지원 프로그램이다. 파트너 지원이 아니다.

지도에서 바뀌는 것 — 정해진 것

  • 연산 분리 — Jetson Thor가 상위 연산을, Jetson Xavier가 VCU를 맡는다.
  • 센서 연결 — LiDAR는 Jetson Thor에 직결하고 상부 카메라를 단다.
  • SLAM·가감속 제어 — FAST-LIO2 대신 직접 만든다.
  • AWS 구성 — AWS IoT Greengrass, AWS IoT Core, Amazon Kinesis Video Streams를 쓴다.
  • Amazon SageMaker AI — RL 정책만 학습하므로 이번엔 쓰지 않는다.
  • 문의 창구 — 메일 루프로 받고, 전문가 네 명 중 한 명이 답한다.

할 일

  • AWS 팀 — 기초 교육 대신 포커스한 교육 아젠다와 가능한 날짜를 뽑는다
  • AWS 팀 — 워크숍 형식과 일정을 정한다
  • 투입 전 세팅 완료 — 8월 말~9월 초
  • 수동 운용으로 현장 투입 — 8월 중순부터
  • VLM 후보 테스트 — 현장 이미지로 Amazon Bedrock 모델을 비교해 고른다
  • 권장제조사 확인 — Ghost Robotics에 저수준 제어 범위를 서면으로 묻는다

지도에서 비어 있는 곳 — 남은 위험·확인할 것

  • 하위단 접근 — Ghost Robotics가 발 모터·가감속 제어를 열어 줄지 모른다.
  • 회수 방식 — SSD 교체, Wi-Fi 자동 업로드, 압축 중 아직 고르지 않았다.
  • 현장 네트워크 — 용인 현장 망을 모르면 실시간 관제가 돌지 장담할 수 없다.
  • 구동시간 — 3시간 이상은 추가 장비 없는 기준이다. 장착 뒤 값은 재지 않았다.
  • 교육 일정 — 날짜가 없다. 늦어지면 에셋을 다시 만들 수 있다. (추정)
확인한 공식 자료
  • Ghost Robotics — Vision 60 사양: 내장 컴퓨터 Jetson Xavier, 연속 보행 3시간 이상
  • NVIDIA Jetson Thor 사양: 1TB NVMe는 개발자 키트 구성품, 모듈은 PCIe로 NVMe 연결
  • Amazon Kinesis Video Streams HLS 재생: 지연 보통 3–5초, 지난 영상 재생 가능
  • AWS IoT Greengrass 모델 배포: Jetson 계열 장치에 배포 가능
  • Isaac Sim AMI (AWS Marketplace): AMI 무료, EC2 비용 별도
  • NVIDIA Video Codec SDK: 2026년 1월부터 Jetson Thor 인코딩 지원
