Vision 60 아키텍처 변경 방안 논의 — 2026년 7월 27일, 1시간 50분

Vision 60을 Jetson Thor 중심 구조로 바꾼다

Jetson Xavier는 VCU만 맡고, 새로 올리는 Jetson Thor가 퍼셉션·플래닝·관제를 맡는다.

클라우드는 AWS IoT Greengrass, AWS IoT Core, Amazon Kinesis Video Streams 세 가지로 시작한다. 제조사가 하위 제어를 어디까지 열어 줄지는 아직 모른다.

  1. 1

    Vision 60을 Jetson Thor 중심으로 바꾸면 무엇이 어디로 가나?

    Jetson Xavier는 VCU, Jetson Thor는 상위 연산

    • 연결은 RJ45 이더넷 — Jetson Thor가 제어 명령을 내리고 Jetson Xavier가 받는다.
    • YOLO 전용 연산 장치 추가 — Jetson Thor에 객체 탐지만 맡는 장치를 올려 전력 소모를 줄인다.
    • 구동시간 기준은 3시간 이상 — 추가 장비가 없을 때 값이고, Vision 60 공식 사양과 같다.

    닫힘역할 분담과 연결 방식은 이 구조로 간다.

  2. 2

    Jetson Thor에서 YOLO를 돌리는데 카메라는 어디에 붙나?

    카메라를 새로 달고, LiDAR는 Jetson Thor에 직결

    • 내장 뎁스 카메라는 바닥을 본다 — 전면 광각 카메라 두 개로도 퍼셉션이 어렵다.
    • 상부 카메라와 고정 LiDAR를 추가 — 둘 다 Jetson Thor에 직접 연결한다.
    • Ghost Robotics 데이터 개방은 제한적 — 약속과 달리 하위단 카메라 접근이 열려 있지 않다.

    닫힘센서는 뎁스 카메라, 상부 카메라, 고정 LiDAR 조합으로 간다.

  3. 3

    위치추정과 보행 제어는 어디까지 직접 하나?

    SLAM과 가감속 제어는 직접 만든다

    • 오도메트리는 LiDAR 내장 IMU로 — 로봇 내장 IMU는 시프트가 생겨 쓰지 않는다.
    • SLAM은 자체 개발 — FAST-LIO2는 실제로 쓰기에 성능이 떨어졌다.
    • 계단 전환은 다리 모터 제어가 필요 — 평지와 경사는 로봇 본체가 알아서 걷는다.

    열림다리 모터를 직접 제어할 수 있는지 아직 모른다.

  4. 4

    로봇 데이터는 클라우드에서 어떻게 모이고 쌓이나?

    클라우드는 세 서비스로 시작한다

    • 핵심은 세 서비스 — 수집·배포에 AWS IoT Greengrass와 AWS IoT Core, 영상에 Amazon Kinesis Video Streams를 쓴다.
    • Amazon SageMaker AI는 이번엔 불필요 — RL 정책만 학습하므로 시뮬레이션에 붙여 바로 학습한다.
    • LiDAR 원시 데이터는 올리지 않는 편이 낫다 — 너무 무거워 온프레미스 처리가 더 빠르다.

    닫힘클라우드 범위는 세 서비스로 좁히고, 파이프라인은 워크숍에서 실습한다.

  5. 5

    현장 관제와 상황 판단은 무엇으로 구현하나?

    산업안전 데모가 설계 초안이다

    • YOLO는 엣지에 배포 — 데모는 Jetson Orin에 AWS IoT Greengrass로 YOLO를 올렸다.
    • 실시간 관제는 망이 있어야 돈다 — 영상은 WebRTC, 메트릭·원격 명령은 MQTT와 Grafana로 보며 직접 개발해야 한다.
    • 비용은 IoT 서비스가 가장 싸다 — Amazon Bedrock은 토큰 과금이고, VLM 모델은 현장 영상으로 테스트해 고른다.

    제안데모 구조가 이번 구성과 거의 같아 그대로 기준으로 삼는다.

  6. 6

    강화학습과 시뮬레이션을 클라우드에서 어떻게 돌리나?

    로컬에서 정의하고, 확장할 때 클라우드로

    • Isaac Sim은 AMI로 바로 띄운다 — Amazon EC2 하나를 현 시스템에 맞춰 세팅한 뒤 복제한다.
    • 파라미터는 일괄 또는 개별 제어 — AWS Batch로 환경 ID·로봇·에폭을 한꺼번에 바꾸고, SSH·DCV·Slurm으로 하나씩 다룬다.
    • 여러 노드가 모델 하나를 학습 — Isaac Lab 학습과 시뮬레이션을 분리하고 공유 스토리지로 동기화한다.

    권고클라우드는 로컬보다 느려서 대규모 확장 테스트 때 옮긴다.

  7. 7

    1시간 찍은 360도 영상을 어떻게 빨리 올리나?

    SSD를 직접 바꾸는 게 가장 빠르다

    • 이더넷 도킹은 거의 쓰지 않는다 — 로봇에서 엣지 장비로 옮기는 속도가 느리고 불안정하다.
    • SSD 교체는 분해가 필요 — SSD를 꽂으려면 그래픽카드를 먼저 떼어내야 한다.
    • Jetson Thor에서 하드웨어 압축 가능 — Video Codec SDK가 2026년 1월부터 Jetson Thor 인코딩을 지원한다.

    열림업로드 방식은 아직 정하지 않았다.

  8. 8

    언제 현장에 가고, 그 전에 무엇을 준비하나?

    투입 전 세팅을 8월 말~9월 초까지 끝낸다

    • 현장은 자주 갈수록 좋다 — 시뮬레이션만으로는 튜닝에 한계가 있어 실측 데이터와 함께 맞춘다.
    • 현장은 용인 — 두 차례 방문과 실측을 기본으로 잡고, 울산은 시험장으로 쓰기 어렵다.
    • 교육은 기초 대신 포커스된 아젠다로 — 이번 지원은 파트너가 아니라 고객 지원 프로그램으로 진행한다.

    열림교육·워크숍 날짜와 아젠다는 아직 없다.

정해진 것

  • 역할 분담 — Jetson Xavier는 VCU, Jetson Thor는 상위 연산을 맡는다. 둘은 RJ45 이더넷으로 잇는다.
  • 센서 조합 — 뎁스 카메라에 상부 카메라와 고정 LiDAR를 더하고, LiDAR는 Jetson Thor에 직결한다.
  • SLAM·가감속 제어 — FAST-LIO2와 Vision 60 기본 가감속 로직 대신 직접 만든다.
  • 클라우드 범위 — AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams로 시작한다.
  • 현장 튜닝 — 시뮬레이션만으로 끝내지 않고 현장에 자주 가서 실측 데이터로 맞춘다.
  • 지원 방식 — 이번 건은 고객 지원 프로그램이고, 문의는 메일 루프로 보낸다.

할 일

  • 지원 팀포커스된 교육 아젠다를 짜고 가능한 날짜를 뽑는다빠른 시일 안
  • 지원 팀워크숍 형식과 일정·아젠다를 뽑는다
  • 미정현장 투입 전 세팅을 끝낸다8월 말~9월 초
  • 지원 팀메일 문의에 전문가 한 명이 답하고 에셋을 공유한다상시
  • 미정현장 영상 판단에 쓸 VLM을 Amazon Bedrock 모델로 테스트해 고른다
  • 미정SK의 첫 건설 산업 사례로 3사 공동 레퍼런스를 만든다

남은 위험·확인할 것

  • 하위 제어 접근 — Ghost Robotics가 다리 모터·카메라 하위단을 열어 줄지 모른다. 연락 창구는 LIG Nex1이다.
  • Jetson Thor 저장 장치 — 공식 사양상 모듈에는 기본 1TB NVMe가 없어 캐리어 보드에 따로 붙여야 한다.
  • 장비를 단 뒤 구동시간 — Jetson Thor(40–130 W)·상부 카메라·LiDAR를 단 상태로 아직 재지 않았다(추정 위험).
  • 데이터 업로드 방식 — SSD 교체, Wi-Fi 자동 업로드, 압축 가운데 기본 경로를 고르지 않았다.
  • 용인 현장 조건 — 현장 네트워크와 방문 시점·담당이 정해지지 않았다. 실시간 관제는 망이 있어야 돈다.
확인한 공식 자료
  • Vision 60 사양 — 내장 컴퓨터는 Jetson Xavier, 연속 보행은 3시간 이상이다.
  • NVIDIA Jetson Thor 사양 — 1TB NVMe는 개발자 키트 구성품이고, 소비 전력은 40–130 W다.
  • Amazon Kinesis Video Streams HLS 재생 — 실시간 재생 지연은 보통 3–5초다.
  • Isaac Sim AMI (AWS Marketplace) — AMI는 무료이고 Amazon EC2 비용은 따로 낸다.
  • LIG Nex1의 Ghost Robotics 인수 — LIG Nex1이 지분 60%를 가진다. 국내 총판 이관은 공식 자료에 없다.
