Vision 60 아키텍처 변경 방안 논의

2026년 7월 27일 10:33–12:24, 1시간 50분

Vision 60의 상위 연산은 Jetson Thor가 맡고, 클라우드는 AWS 서비스 세 가지로 시작합니다.

Jetson Xavier는 VCU로 남아 하위 제어를 맡습니다. 제조사의 하위 제어 개방 범위와 영상 업로드 방식은 아직 모릅니다.

요점

  1. ①
    Jetson Xavier — VCU로 액추에이터 제어·기본 통신 담당, 계단 전환 시 모터 제어 개방 범위 미확인
  2. ②
    RJ45 이더넷 — 두 컴퓨터를 잇는 유일한 링크, 카메라 데이터와 제어 명령이 함께 이동 (대역폭 검토 없음, 추정)
  3. ③
    Jetson Thor — 관제·주행 플래닝·매핑·YOLO를 전담, 상부 카메라와 LiDAR를 직접 연결
  4. ④
    엣지–클라우드 연결 — AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams 세 가지로 시작, 영상은 약 4초 지연
  5. ⑤
    Amazon Bedrock — YOLO confidence가 낮은 장면만 VLM 판단 요청, 토큰 기반 과금
  6. ⑥
    대용량 업로드 — SSD 물리 교체가 가장 빠른 방법, 기본 업로드 방식 미정
  7. ⑦
    데이터·학습 — Amazon S3에 L0(원시)·L1(가공)·L2 저장, Isaac Sim·Isaac Lab 학습은 Amazon EC2·AWS Batch로 확장

  • 센서 구성 — 상부 카메라 추가, LiDAR는 Jetson Thor에 직접 연결
  • SLAM·가감속 제어 — FAST-LIO2 대신 자체 개발
  • 클라우드 시작 구성 — 핵심 서비스 세 가지로 시작, Amazon SageMaker AI는 이번엔 제외
  • 지원 방식 — 고객 지원 프로그램으로 진행, 문의는 메일 루프로 전달

  • Ghost Robotics 개방 범위 — 데이터·하위단 접근과 발 모터 제어 가능 여부 미확인
  • 구동시간 — Jetson Thor·상부 카메라·LiDAR 탑재 후 미측정, 3시간 이상은 추가 장비 없는 기준
  • 영상 업로드 방식 — SSD 교체·Wi-Fi 자동 업로드·압축 중 기본 방식 미정
  • Jetson Thor 저장 구성 — 1TB NVMe는 개발자 키트 구성품, 모듈용 저장 장치 구성 미정
  • 현장 네트워크 — 실시간 관제는 네트워크 연결이 전제, 용인 현장 망 조건 미확인

흐름

1Vision 60의 연산을 두 컴퓨터에 어떻게 나눌까요?

Jetson Xavier는 하위 제어, Jetson Thor는 상위 연산을 맡습니다. 두 컴퓨터는 RJ45 이더넷으로 연결합니다.

  • 연결 — Vision 60 본체의 RJ45 단자로 이더넷 통신
  • 카메라 — 내장 뎁스 카메라가 바닥 방향이라 상부에 퍼셉션용 카메라 추가
  • 전력 — 구동시간 3시간 이상 목표, YOLO 전용 연산 장치로 전력 절감 계획

2보행과 위치 추정은 어디까지 직접 만들까요?

평지·경사 보행은 Vision 60 본체에 맡깁니다. SLAM과 가감속 제어는 직접 만듭니다.

  • SLAM — FAST-LIO2는 실사용 성능 부족, 개량·자체 개발 중
  • 오도메트리 — 내장 IMU는 시프트 발생, LiDAR 내장 IMU 사용
  • 제조사 — Ghost Robotics의 데이터 개방이 약속보다 제한적이라는 우려, 하위단 접근 가능 여부 미확인

3클라우드 서비스는 무엇부터 쓰면 될까요?

AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams 세 가지면 됩니다. AWS 산업안전 데모가 이 구성입니다.

  • 데모 구성 — Unitree Go2·Jetson Orin에 YOLO를 AWS IoT Greengrass로 배포, AWS IoT Core(MQTT)·Grafana로 메트릭·원격 제어
  • Amazon SageMaker AI — RL 정책만 학습한다면 이번엔 불필요
  • 전제 조건 — 네트워크 연결이 필요한 실시간 구성, 기능별 직접 개발 필요

4강화학습은 언제 클라우드로 옮길까요?

환경과 알고리즘은 로컬 PC에서 먼저 정합니다. 대규모 확장 테스트 때 클라우드로 옮깁니다.

  • 일괄 설정 — AWS Batch로 환경 ID·로봇·학습 에폭 등 파라미터를 한 번에 지정
  • 분산 학습 — Isaac Lab 학습과 시뮬레이션을 분리, 공유 스토리지로 체크포인트 공유
  • 확인 — 학습된 정책 동작과 로그를 클라우드에서 바로 확인

51시간 분량 360도 영상을 어떻게 옮길까요?

지금은 SSD를 직접 교체해 옮기는 방법이 가장 빠릅니다. 기본 방식은 아직 정하지 않았습니다.

  • SSD 교체 — Jetson Thor의 SSD를 꽂으려면 그래픽카드를 먼저 분리하는 구조
  • 압축 — NVIDIA 인코더 압축 대안, 10배 이상 차이라는 수치는 출처 미확인
  • LiDAR 원시 데이터 — 너무 무거워 업로드보다 온프레미스 처리가 빠를 가능성

6현장 투입 전까지 무엇을 맞춰야 하나요?

교육·워크숍을 투입 전 세팅 일정에 맞춥니다. 날짜와 아젠다는 아직 없습니다.

  • 현장 방문 — 시뮬레이션만으로는 튜닝 한계, 실측 데이터와 함께 개발 (울산은 시험장으로 어려움)
  • 지원 체계 — 파트너 지원이 아닌 고객 지원 프로그램, 전문가 네 명이 메일로 답변
  • 공동 레퍼런스 — SK의 첫 건설 산업 사례로 3사 공동 레퍼런스 구상, Seoul Dynamics는 파트너로 참여

공식 자료 대조

  • Ghost Robotics — Vision 60 제품·기술 사양확인됨
    내장 컴퓨터 Jetson Xavier, 연속 보행 3시간 이상과 일치. 뎁스 카메라 장착 방향은 사양에 없음.
  • Ghost Robotics Corporation and LIG Nex1 Announce Close of Acquisition확인 불가
    LIG Nex1의 2024년 7월 지분 60% 인수는 확인. KRM 종료와 국내 총판 이관 자료는 없음.
  • NVIDIA Jetson Thor — 모듈·개발자 키트 사양상이함
    1TB NVMe는 개발자 키트 구성품, 모듈은 PCIe로 NVMe 연결. 소비 전력 40–130 W.
  • hku-mars/FAST_LIO (FAST-LIO2)확인 불가
    외부 IMU 지원 패키지. 실사용 성능 부족은 현장 경험 판단이라 문서로 검증 불가.
  • Video playback with HLS — Amazon Kinesis Video Streams확인됨
    HLS 재생 지연 보통 3–5초, 지난 영상 재생과 WebRTC 지원. 함께 볼 자료: FAQ
  • Deploy a Model (AWS IoT Greengrass) — Amazon SageMaker AI확인됨
    Jetson 계열 장치로 AWS IoT Greengrass 모델 배포 가능. 사례: YOLOv8 on GPU edge devices
  • Models at a glance — Amazon Bedrock확인됨
    Anthropic·OpenAI·NVIDIA 모델 제공은 일치. 언급된 Claude 모델명은 직접 확인 못 함. 함께 볼 자료: Model Choice
  • AWS Marketplace: NVIDIA Isaac Sim Development Workstation확인됨
    Isaac Sim AMI는 무료, Amazon EC2 인프라 비용 별도. SSH·DCV 접속 안내와 일치. 설치 안내: AWS Deployment
  • Scale Reinforcement Learning with AWS Batch Multi-Node Parallel Jobs확인됨
    AWS Batch 다중 노드로 Isaac Lab 분산 학습, 체크포인트는 Amazon EFS에 저장. 함께 볼 자료: Isaac Lab in VAMS
  • NVIDIA Video Codec SDK (NVENC/NVDEC)확인 불가
    2026년 1월 Jetson Thor 인코딩 지원 추가. 10배 이상 압축 수치는 출처에 없음.

조회일 2026-10-28, 웹 검색 10회.

시사점

  • 추정데모 구성 재사용 — 산업안전 데모의 Jetson Orin 자리에 Jetson Thor를 넣는 방식이 새 설계보다 빠름, 해당 구조가 그대로 맞는다는 평가
  • 추정예외 상황 판단 — 바닥 물 같은 룰 기반 플래너의 예외에 Amazon Bedrock VLM 구성 적용 가능, 지연 때문에 주행이 아닌 상황 판단용

리스크

  • 추정이더넷 대역폭 — 카메라 데이터와 제어 명령이 같은 링크 공유, 지연이 제어에 영향 가능
  • 추정구동시간 — 추가 장비 전력이 더해지면 1시간 단위 수집과 충전 중 업로드 계획이 함께 변동
  • 추정교육 일정 — 워크숍이 세팅보다 늦으면 아키텍처에 맞지 않는 에셋 재작업 반복 가능
  • 추정SSD 교체 부담 — 그래픽카드 분리가 필요해 현장 반복 작업에 부적합 가능

기회

  • 추정Jetson Thor 하드웨어 인코딩 — 장치에서 압축한 뒤 충전 중 도킹·Wi-Fi로 올리는 조합이 SSD 교체 대안 후보

권장 후속 조치

  • 제조사 서면 확인 — 발 모터 제어·가감속 제어 교체·카메라 하위 접근 가능 여부, LIG Nex1 연락 경로 활용
  • 저장 구성과 데이터 회수 방식 — 캐리어 보드 NVMe 구성과 외부 USB SSD 안을 함께 결정
  • 수동 운용 전 측정 — 전체 장비 탑재 구동시간, NVENC 압축 후 360도 영상 1시간 용량
  • 다음 미팅 안건 — Jetson Xavier–Jetson Thor 인터페이스 명세, 용인 현장 네트워크와 업로드 경로
