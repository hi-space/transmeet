핵심 메시지

Vision 60은 Jetson Thor가 상위 연산을 맡고 Jetson Xavier가 VCU로 남는 구조로 바뀝니다.

  • 연산 역할 분담 — Jetson Thor는 관제·주행 플래닝·매핑·퍼셉션, Jetson Xavier는 액추에이터 제어·기본 통신으로 역할 분담 확정
  • AWS 핵심 서비스 — AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams 세 가지로 한정, RL 정책만 학습하면 Amazon SageMaker AI 불필요
  • 센서 재배치 — LiDAR는 Jetson Thor에 직결하고 퍼셉션용 상부 카메라를 별도로 추가
  • 투입 일정 — 8월 중순 수동 운용 투입, 8월 말~9월 초 투입 전 세팅 완료 목표
  • 남은 위험 — Ghost Robotics 하위단 개방 범위와 대용량 데이터 회수 방식 미정

백그라운드

  • 미팅 목적 — Vision 60 아키텍처 파악과 교육 방향 조기 확정
  • 에셋 재작업 경험 — 아키텍처를 모른 채 만든 에셋을 쓰지 못한 경험, 현장 방문 전에 에셋을 이미 제작한 상태
  • 구조 변경 대상 — Ghost Robotics 방식으로 구성된 Vision 60을 Jetson Thor 중심 구조로 변경
  • 로봇 선정 경위 — 중국산 제외 조건으로 Spot 등 후보를 비교한 뒤 Ghost Robotics 선정
  • 지원 형태 — AWS 팀의 고객 지원 프로그램으로 기획, 파트너 지원은 별도 파트너 팀 소관

회의 요약

#

주요 논의

  • 연산 역할 분담 — Jetson Xavier는 VCU, Jetson Thor는 상위 연산, 두 장치는 Vision 60의 RJ45 커넥터로 이더넷 통신
  • 센서 배치 — 내장 뎁스 카메라·광각 카메라가 모두 바닥 방향이라 퍼셉션용 상부 카메라 추가, LiDAR는 Jetson Thor에 직결
  • 제조사 데이터 개방 — 일부 개방 약속과 달리 실제 범위는 제한적일 우려, 하위단 접근 범위 미확인
  • 오도메트리·SLAM·가감속 제어 — LiDAR 내장 IMU로 오도메트리 구성, FAST-LIO2 대신 자체 SLAM 개발, 가감속 제어는 Jetson Thor에서 전달
  • AWS 서비스 범위 — 핵심은 AWS IoT Greengrass·AWS IoT Core·Amazon Kinesis Video Streams, 데이터는 Amazon S3에 L0·L1·L2 계층으로 저장
  • 산업안전 데모 구조 — Jetson Orin 위 YOLO 판단을 우선하고 신뢰도가 낮은 경우만 Amazon Bedrock VLM으로 전송하는 구성 제안
  • 클라우드 시뮬레이션 학습 — 로컬 PC에서 환경·알고리즘을 먼저 정의하고 대규모 확장 테스트 때만 Amazon EC2·Isaac Sim으로 이전 권장
  • 대용량 데이터 회수 — SSD 물리 교체가 가장 빠르지만 사람 개입 필요, 회수 방식 미정
  • 일정·교육 — 8월 중순 수동 운용 투입, 교육 아젠다·날짜·워크숍 일정은 AWS 팀이 산출

전체 구조

  1. ①

    Jetson Xavier는 VCU

    • Vision 60 내장 컴퓨터는 Jetson Xavier(제조사 사양 확인)
    • 액추에이터 제어·기본 통신 담당, Jetson Thor의 제어 명령 수신
    • 모터와 내장 카메라는 Jetson Xavier 쪽에 연결
    • 계단 전환 시 발 모터단 직접 제어 필요, Ghost Robotics 저수준 접근 범위 미확인
  2. ②

    Jetson Thor는 상위 연산

    • 관제·주행 플래닝·매핑·퍼셉션·추론 전담
    • 개발자 키트 대신 모듈 사용, 1TB 저장 장치에 필요 시 SSD 추가
    • 1TB NVMe는 개발자 키트 구성품, 모듈은 캐리어 보드에 NVMe 별도 구성 필요
    • 소비 전력 40–130 W, YOLO 전용 연산 장치로 전력 절감 계획(장치 명칭 미확인)
  3. ③

    센서 조합

    • 내장 뎁스 카메라 2개와 전면 광각 카메라 2개는 바닥 방향
    • 퍼셉션용 상부 카메라 별도 추가
    • 고정형 LiDAR는 Jetson Thor에 직결
    • 공식 기본 센서는 RGB 카메라 5대·D435 뎁스 센서 4대, 장착 방향은 사양 미기재
  4. ④

    RJ45 이더넷 링크

    • Jetson Xavier와 Jetson Thor는 Vision 60의 RJ45 커넥터로 이더넷 통신
    • Jetson Xavier 카메라 데이터는 YOLO 추론용으로 Jetson Thor에 재전송 필요
    • 하위단 카메라 이전은 접근이 열려 있지 않아 곤란
    • 제어 명령·센서 데이터를 함께 실을 때의 대역폭·지연 미검토(추정 리스크)
  5. ⑤

    AWS IoT Greengrass · AWS IoT Core

    • AWS IoT Greengrass는 클라우드 학습 모델을 Jetson 계열 엣지 장치로 배포(공식 문서 확인)
    • AWS IoT Core는 MQTT로 실시간 메트릭 수집·원격 제어 명령 전달
    • 처음 혼자 구성하기는 어렵지만 워크숍 한 번으로 파이프라인 습득 가능
    • 비용은 AWS IoT Greengrass·AWS IoT Core가 가장 저렴
  6. ⑥

    Amazon Kinesis Video Streams

    • 카메라 영상을 WebRTC·HLS로 실시간 시청
    • 약 4초 지연, 공식 문서상 HLS 지연은 보통 3–5초(범위 1–10초)
    • 지난 영상 재생 가능, ROS bag 재생과 같은 방식으로 활용
    • 실시간 구성은 현장 네트워크 연결 전제
  7. ⑦

    Amazon S3 데이터 레이크 · Amazon EKS

    • Amazon S3에 L0(원시)·L1(가공)·L2 계층, 하이브 파티셔닝으로 저장
    • Amazon EKS로 처리, 메타 정보는 DynamoDB에 저장
    • 비디오 데이터 90% 이상은 쓸모없어 구간 분할·선별 필요
    • LiDAR 원시 데이터는 용량이 커 온프레미스 처리가 더 빠를 가능성
  8. ⑧

    Amazon Bedrock VLM

    • 엣지에서 YOLO·결정 트리로 먼저 판단
    • 신뢰도가 낮은 경우만 Amazon Bedrock VLM으로 전송
    • 이유는 클라우드 왕복·추론 시간, 과금은 토큰 기반
    • 모델은 현장 영상 테스트 후 선정
  9. ⑨

    오프라인 데이터 회수

    • 1시간 360도 영상의 무선 업로드에 매우 긴 시간 소요, 이더넷은 느리고 불안정
    • SSD 물리 교체는 가장 빠르지만 사람 개입 필요
    • 특정 Wi-Fi 자동 업로드는 밤새 소요, NVIDIA 인코더 압축은 대안 후보
    • 회수 방식 미정

회의 결과

#

결정 사항 11건

  • Jetson Xavier는 VCU, Jetson Thor는 상위 연산일반적인 자율주행·로보틱스 구조와 맞추기 위한 분담이며, Jetson Xavier가 Jetson Thor의 제어 명령을 받습니다.
  • RJ45 이더넷으로 두 장치 연결Vision 60에 이미 있는 인터페이스를 쓰지만 대역폭과 지연은 아직 검토하지 않았습니다.
  • LiDAR 직결과 상부 카메라 추가내장 뎁스 카메라와 광각 카메라가 바닥을 향하고 하위단 카메라 접근도 열려 있지 않기 때문입니다.
  • 오도메트리는 LiDAR 내장 IMU로 구성Vision 60 내장 IMU는 시프트가 생겨 쓰지 않습니다.
  • FAST-LIO2 대신 자체 SLAM 사용FAST-LIO2는 실사용 성능이 부족합니다. 자체 SLAM은 다층·3D 구조에 대응하도록 개량해 개발 중입니다.
  • 가감속 제어는 Jetson Thor의 자체 로직Vision 60 기본 가감속 로직으로는 자체 알고리즘을 얹을 수 없어 Vision 60은 기본 제어만 맡습니다.
  • AWS 핵심 서비스 세 가지로 한정RL 정책만 학습하면 Amazon SageMaker AI는 쓰지 않습니다. VLA 등 별도 모델을 학습하게 되면 다시 검토합니다.
  • 현장 투입은 수동 운용으로 시작시뮬레이션만으로는 튜닝에 한계가 있어 8월 중순부터 현장에 자주 투입해 실측 데이터로 튜닝합니다.
  • 기초 교육 대신 집중 교육8월 말~9월 초 투입 전에 세팅을 끝내기 위한 결정입니다. 아키텍처에 맞지 않는 에셋을 다시 만드는 일도 막습니다. 아젠다·날짜·워크숍 일정은 AWS 팀이 산출합니다.
  • 문의는 메일 루프로 접수전문가 4명 중 1명이 답하고 관련 에셋을 공유합니다.
  • 고객 지원 프로그램으로 진행AWS 팀은 원래 파트너를 지원하지 않으며 파트너 지원은 별도 파트너 팀이 맡습니다.

미결 사항 10건

  • 교육·워크숍 날짜와 아젠다8월 말~9월 초 투입 전 세팅 일정이 이 날짜에 달려 있습니다. 늦어지면 에셋 재작업이 반복될 수 있습니다(추정).
  • Ghost Robotics 하위단 개방 범위계단 전환 시 발 모터 제어, 자체 가감속 제어, 카메라 재배치가 모두 이 범위에 달려 있습니다.
  • Jetson Thor 장착 후 구동시간3시간 이상은 추가 장비가 없을 때 기준입니다. Jetson Thor(40–130 W)·상부 카메라·LiDAR를 단 상태의 값은 아직 측정하지 않았습니다. 이 값은 현장 수집과 충전 중 업로드 계획에 영향을 줍니다(추정).
  • Jetson Thor 모듈의 저장 장치 구성1TB NVMe는 개발자 키트 구성품입니다. 모듈은 캐리어 보드에 NVMe를 따로 붙여야 합니다. SSD를 교체하려면 분해가 필요합니다.
  • 대용량 데이터 업로드 방식1시간 360도 영상도 업로드에 매우 오래 걸립니다. SSD 교체·USB SSD·Wi-Fi 자동 업로드·압축 중 어느 것도 정하지 않았습니다. 압축률 10배 이상이라는 수치도 검증하지 않았습니다.
  • Jetson Xavier–Jetson Thor 이더넷 대역폭·지연카메라 데이터와 제어 명령이 같은 링크에 실려 제어 지연이 생길 수 있습니다(추정).
  • 현장 네트워크 조건Amazon Kinesis Video Streams·AWS IoT Core·Grafana 실시간 관제는 네트워크 연결이 전제입니다. 용인 현장 망 조건은 아직 모릅니다.
  • 현장 방문 시점·담당용인 실측과 두 차례 방문을 기본안으로 잡았습니다. 방문 1회에 하루 종일 걸립니다. 방문 일정과 담당은 정하지 않았습니다.
  • VLM 모델 선정현장 특화 VLM이 없습니다. 정확도와 응답 지연을 테스트로 확인해야 합니다.
  • KRM에서 LIG Nex1로의 총판 이관공식 자료로 확인하지 못했습니다. 이관 여부는 제조사 연락 경로에 영향을 줍니다.

공식 자료 대조

  • Ghost Robotics — Vision 60 제품·기술 사양일치
    내장 컴퓨터 Jetson Xavier와 연속 보행 3시간 이상은 일치하지만, 뎁스 카메라가 바닥을 향한다는 점은 사양에 장착 방향이 없어 확인할 수 없습니다.
  • Ghost Robotics Corporation and LIG Nex1 Announce Close of Acquisition확인 불가
    LIG Nex1의 2024년 7월 지분 60% 인수는 확인되지만 KRM 종료와 국내 총판 이관은 이 출처에 없습니다.
  • NVIDIA Jetson Thor — 모듈·개발자 키트 사양다름
    1TB NVMe는 개발자 키트 구성품이라 모듈만 쓰면 캐리어 보드에 저장 장치를 따로 구성해야 하며, 소비 전력은 40–130 W입니다.
  • hku-mars/FAST_LIO (FAST-LIO2) GitHub확인 불가
    회전형·고정형 LiDAR와 외부 IMU 지원은 확인되지만 실사용 성능 부족은 현장 경험에 따른 판단이라 검증할 수 없습니다.
  • Video playback with HLS — Amazon Kinesis Video Streams일치
    HLS 지연이 보통 3–5초이고 지난 영상 재생을 지원해 약 4초 지연이라는 설명과 일치합니다.
  • Deploy a Model (AWS IoT Greengrass) — Amazon SageMaker AI일치
    클라우드에서 학습한 모델을 AWS IoT Greengrass로 NVIDIA Jetson 계열 엣지 장치에 배포하는 방식이 설명과 일치합니다.
  • Models at a glance — Amazon Bedrock일치
    Anthropic·OpenAI·NVIDIA 등 여러 공급사 모델 제공은 일치하지만 언급된 Claude 모델명은 직접 확인하지 못했습니다.
  • AWS Marketplace: NVIDIA Isaac Sim™ Development Workstation (Linux)일치
    Isaac Sim 설치 AMI는 무료이고 Amazon EC2 인프라 비용은 따로 내며, SSH·DCV 접속(TCP 22·8443)도 안내와 같습니다.
  • Scale Reinforcement Learning with AWS Batch Multi-Node Parallel Jobs일치
    AWS Batch 다중 노드 병렬 작업으로 Isaac Lab을 분산하고 체크포인트를 Amazon EFS에 저장하는 구성이 설명과 일치합니다.
  • NVIDIA Video Codec SDK (NVENC/NVDEC)확인 불가
    2026년 1월부터 Jetson Thor를 지원하지만 10배 이상 압축이라는 수치는 출처에 없고 코덱·비트레이트에 따라 달라집니다.
